# Quickstart: Validating Overdue Todo Items

This guide describes how to run and manually validate the overdue-indicator feature end-to-end.
It intentionally does not repeat implementation code — see
[data-model.md](/workspaces/ae-bootcamp-lab-6-aschott/specs/001-overdue-todo-items/data-model.md)
and
[contracts/is-overdue-contract.md](/workspaces/ae-bootcamp-lab-6-aschott/specs/001-overdue-todo-items/contracts/is-overdue-contract.md)
for the behavioral contract, and `tasks.md` (generated by `/speckit-tasks`) for the implementation
breakdown.

## Prerequisites

- Node.js v16+ and npm v7+ installed (per `docs/project-overview.md`).
- Dependencies installed once at the repo root: `npm install`.

## Automated Validation

Run the frontend test suite, which should include the new `isOverdue` unit tests and the updated
`TodoCard` component tests:

```bash
npm run test:frontend
```

Or, to run just the new/changed test files during development:

```bash
npm test --workspace=frontend -- todoStatus
npm test --workspace=frontend -- TodoCard
```

**Expected outcome**: All tests pass, and coverage for the new `src/utils/todoStatus.js` module
and the modified `TodoCard.js` branches meets the project's 80%+ coverage target (per
`docs/testing-guidelines.md` and the constitution).

## Manual Validation

1. Start the app from the repo root:
   ```bash
   npm run start
   ```
2. Open the app in a browser (default React dev server URL).
3. Create four todos via the "Add a new todo..." form to cover the key scenarios:
   - A todo with a due date a few days in the past (leave incomplete).
   - A todo with a due date of today (leave incomplete).
   - A todo with a due date a few days in the future (leave incomplete).
   - A todo with a due date in the past, then mark it complete via its checkbox.
4. **Expected**: Only the first todo (past due date, incomplete) displays the non-color
   "Overdue" badge/label. The today, future, and completed-past-due todos do not.
5. Mark the overdue todo complete: **Expected** — the "Overdue" badge disappears immediately,
   with no page reload.
6. Re-open (mark incomplete) that same todo: **Expected** — the "Overdue" badge reappears
   immediately, since its due date is still in the past.
7. Edit the overdue todo's due date to a future date: **Expected** — the "Overdue" badge
   disappears immediately upon saving the edit.
8. Create a todo with no due date at all: **Expected** — it never shows the "Overdue" badge,
   regardless of completion state.
9. Toggle dark/light mode: **Expected** — the "Overdue" badge remains legible and consistent
   with the existing danger-color styling in both themes (per `docs/ui-guidelines.md`).

## Success Criteria Mapping

Each manual step above corresponds to a spec Success Criterion:

- Steps 3–4 → SC-001, SC-002, SC-003 (correct, at-a-glance identification; no false positives).
- Steps 5–7 → SC-004 (indicator reflects true status within 1 second, no reload).
- Step 8 → SC-003 (todos without a due date never shown as overdue).
